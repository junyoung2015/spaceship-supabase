# v0.2 target-context contract

- **Status:** accepted product decision for [issue #4](https://github.com/junyoung2015/spaceship-supabase/issues/4); it authorizes no feature code by itself.
- **Applies to:** planned **v0.2.0** human-readable target-context work.
- **Research basis:** [Supabase CLI project-name and target-context research](../research/supabase-cli-project-names.md).
- **Follow-on issues:** [#5](https://github.com/junyoung2015/spaceship-supabase/issues/5), [#6](https://github.com/junyoung2015/spaceship-supabase/issues/6), [#7](https://github.com/junyoung2015/spaceship-supabase/issues/7), and [#8](https://github.com/junyoung2015/spaceship-supabase/issues/8).

## Decision

The full validated 20-character Supabase project ref remains the only target
identity. Human-readable text is a decoration bound to that ref: it can make a
target easier to recognize, but it can never select, replace, restore, or
authorize one.

v0.2 makes three categories intentionally distinct:

1. A **manual label** is local text chosen by the user for operational
   recognition, such as Production or Customer staging.
2. A **synced decoration** is a point-in-time, user-confirmed remote project or
   hosted-branch description saved outside the prompt path. It is visibly
   marked as synced and is never claimed to be network-fresh at render time.
3. A **local database branch** is optional local database state. It remains
   explicitly labeled `local-db:` and is never presented as a hosted branch.

This record settles vocabulary, output forms, privacy defaults, precedence, and
provenance. It does not add a remote adapter, sync command, or linked-project
parser; those require their own implementation, security, and compatibility
gates.

## Vocabulary

| Term | Precise meaning | Identity authority? | Prompt eligibility |
| --- | --- | --- | --- |
| **Live ref** | The exact 20-lowercase-letter value currently read from a safe project-ref file under the selected root. | **Yes.** Stable local identity. | Always, when valid. |
| **Configured mapping** | The exact ref in the explicitly selected named remote mapping when no live ref is valid. Its name is a local selector, not proof of an environment. | Non-live fallback identity only. | Yes, with `configured:<name>`. |
| **Project name** | A human-readable name returned for one top-level Supabase project by an explicit authenticated lookup. | No. | Only as a validated synced decoration or manual label. |
| **Manual label** | User-authored local text keyed by a project ref, for example Production or Do not touch. | No. | In label-plus-ref format when the current resolved ref matches. |
| **Synced decoration** | A separately stored, user-confirmed point-in-time remote project or hosted-branch description keyed by a live ref, with provenance and fetch time. | No. | Opt-in, label-plus-ref only, while that exact live ref is current. |
| **Hosted branch** | A remote Supabase Branch whose branch-project ref was uniquely matched through an explicit lookup under a known parent project ref. | No. | Only as a synced decoration after that exact proof. |
| **Local database branch** | The validated local value in the stable CLI local DB-branch file. It belongs to local database branching. | No. | Optional trailing `local-db:<name>` marker with a live ref only. |
| **Linked-project snapshot** | The undocumented telemetry cache written by some stable CLI versions. | No. | Not approved unless [#5](https://github.com/junyoung2015/spaceship-supabase/issues/5) reaches a separate go decision. |

### Naming rules

- Say **configured mapping**, not “environment,” for `configured:<remote>`.
  A selector named staging is useful local context, not proof of hosted
  environment semantics.
- Say **manual label** for user-authored text. Never present it as a remote
  project name.
- Say **synced project decoration** or **synced hosted-branch decoration** for
  data from an explicit lookup. Do not call it current, live, or fresh after it
  has been saved.
- Reserve **hosted branch** for an exact remote branch-project-ref match. Git
  branches, directory names, config remote names, and local DB branch state
  never establish hosted-branch identity.
- `ref@branch` remains prohibited. It falsely suggests a hosted relationship.

## Identity selection before decoration

The resolver must choose identity without inspecting labels, synced state, or a
prior prompt result:

| Rank | Preconditions | Selected identity | Required visible provenance |
| --- | --- | --- | --- |
| 1 | Safe root and valid live project-ref | Live ref | The exact full ref. |
| 2 | No valid live ref; safe, selected config mapping | Configured ref | `configured:<remote>` |
| 3 | Anything else | No segment | None; normal failure is silent. |

No decoration can find a root, choose a ref, recover a missing ref, or cross a
project boundary. The full ref remains visible in every form below.

## Exact display forms

The existing format modes remain the only display modes:

- **ref** is the compact default. It never shows a manual label or synced
  decoration.
- **label+ref** permits a validated manual label or opt-in synced decoration
  before the full ref.

The `🔷 ` below represents the user-configured symbol. Punctuation and textual
provenance are contractual; color is never the only distinction.

| Situation | ref output | label+ref output | Source and fallback |
| --- | --- | --- | --- |
| Valid live ref, no usable decoration | `🔷 abcdefghijklmnopqrst` | `🔷 abcdefghijklmnopqrst` | Live ref only. |
| Matching manual label Production | `🔷 abcdefghijklmnopqrst` | `🔷 Production (abcdefghijklmnopqrst)` | Manual label wins over automatic decoration. |
| Matching synced project name Customer API | `🔷 abcdefghijklmnopqrst` | `🔷 Customer API (abcdefghijklmnopqrst) · synced:project` | Requires label+ref, sync opt-in, and a valid matching record. |
| Matching synced hosted branch Customer API / qa-482 | `🔷 abcdefghijklmnopqrst` | `🔷 Customer API / qa-482 (abcdefghijklmnopqrst) · synced:hosted-branch` | Requires the exact hosted-branch proof below. |
| Configured mapping staging, no manual label | `🔷 abcdefghijklmnopqrst · configured:staging` | `🔷 abcdefghijklmnopqrst · configured:staging` | Non-live identity; synced decoration never applies. |
| Configured mapping and manual label Production | `🔷 abcdefghijklmnopqrst · configured:staging` | `🔷 Production (abcdefghijklmnopqrst) · configured:staging` | Label decorates the ref; mapping marker remains. |
| Live ref plus local DB branch feature/refactor-42 | `🔷 abcdefghijklmnopqrst (local-db:feature/refactor-42)` | `🔷 abcdefghijklmnopqrst (local-db:feature/refactor-42)` | Existing local-DB opt-in; not a hosted branch. |
| Manual label plus local DB branch | `🔷 abcdefghijklmnopqrst (local-db:feature/refactor-42)` | `🔷 Production (abcdefghijklmnopqrst) (local-db:feature/refactor-42)` | The local marker remains a separate suffix. |
| Synced hosted branch plus local DB branch | `🔷 abcdefghijklmnopqrst (local-db:feature/refactor-42)` | `🔷 Customer API / qa-482 (abcdefghijklmnopqrst) · synced:hosted-branch (local-db:feature/refactor-42)` | The two branch concepts stay distinct. |

`synced:project` and `synced:hosted-branch` mean that a user explicitly
approved a remote lookup at an earlier time. They do **not** assert that the
name is fresh at this prompt. After [#6](https://github.com/junyoung2015/spaceship-supabase/issues/6) ships,
verbose doctor output must show the sanitized source and saved-at time.

The prompt never truncates a ref, replaces the ref with a name, or chooses a
different form based on terminal width. A narrow terminal may wrap. Users who
want the smallest stable form select ref format.

## Decoration precedence

For a selected identity, apply this tree on every render:

```text
selected live ref
  ├─ format is ref → full ref only
  └─ format is label+ref
       ├─ matching enabled manual label → manual label + full ref
       ├─ matching enabled synced decoration → synced text + full ref + synced:<kind>
       └─ otherwise → full ref only

selected configured ref
  ├─ format is ref → full ref + configured:<remote>
  └─ format is label+ref
       ├─ matching enabled manual label → manual label + full ref + configured:<remote>
       └─ otherwise → full ref + configured:<remote>
```

Append the optional local database marker only after choosing a live-ref form.
It never decorates a configured mapping.

Consequences:

- Manual-label precedence is **display** precedence, not identity precedence.
  A live ref still wins over a configured mapping even if the latter has a
  label and the live ref does not.
- A matching enabled manual label intentionally hides a synced decoration in
  the prompt. Verbose doctor must report a valid synced record as **shadowed**,
  not as an error.
- The manual-label clear operation removes only the manual record. If synced
  display is enabled, a matching synced decoration can appear on the next live
  render after clear.
- Disabling the existing label-read setting suppresses only manual-label reads.
  It does not alter manual-label or synced-decoration records.
- Synced decorations are live-only. They never decorate a configured mapping,
  even when the ref happens to match a saved record.
- The linked-project telemetry file has no display form or precedence rank
  until #5 makes a separate decision.

## Privacy and opt-in defaults

The privacy-preserving default remains the current ref-only prompt:

```zsh
SPACESHIP_SUPABASE_FORMAT="ref"
```

No human name is shown by default. A user must choose label+ref and, for
remote-derived text, enable the planned synced-decoration read switch:

| v0.2 setting | Default | Contract |
| --- | --- | --- |
| `SPACESHIP_SUPABASE_FORMAT` | `ref` | Existing mode; label+ref is required before a human-readable decoration renders. |
| `SPACESHIP_SUPABASE_USE_LABELS` | `true` | Existing local-label read switch; it has no visible effect in ref mode. |
| `SPACESHIP_SUPABASE_USE_SYNCED_DECORATIONS` | `false` | New explicit opt-in before saved remote-derived text can enter a prompt. |
| `SPACESHIP_SUPABASE_SYNCED_DECORATION_FILE` | `${XDG_STATE_HOME:-$HOME/.local/state}/spaceship-supabase/decorations.tsv` | New absolute, owner-controlled separate store. |

The future sync helper must not edit shell configuration, change those settings,
or make a remote name visible simply because it ran. It may show the exact
configuration needed to opt in after a successful save.

Names reveal more operational context than a raw ref. Treat prompts,
screenshots, recordings, shared logs, and verbose doctor output accordingly.
Default doctor output reports fixed redacted statuses only. It must not reveal
values, paths, credentials, CLI output, or timestamps. Verbose doctor output
is an explicit request to show only already validated values, kind, source, and
saved-at time.

## Synced-decoration provenance and storage

A synced decoration is not a second label. It uses a separate, versioned,
owner-only state file so a remote lookup can neither overwrite nor be mistaken
for user-owned operational vocabulary.

Each validated record must carry these logical fields:

| Field | Required for | Rule |
| --- | --- | --- |
| `version` | Every record | Strict schema evolution; unknown versions are ignored. |
| `ref` | Every record | Exact validated key; equals the current live ref at render time. |
| `kind` | Every record | Exactly `project` or `hosted-branch`. |
| `project_name` | Every record | Validated prompt-safe text. |
| `branch_name` | Hosted branch | Validated prompt-safe text; absent for a top-level project. |
| `parent_ref` | Hosted branch | Exact validated parent ref used for lookup. |
| `source` | Every record | Fixed explicit-lookup source, such as `supabase-cli:projects-list` or `supabase-cli:projects-list+branches-list`. |
| `fetched_at` | Every record | Bounded UTC epoch timestamp for auditability, not a prompt-time freshness claim. |

Remote text must pass the manual-label safety policy: 1–64 printable ASCII
characters, no percent sign, tab, newline, carriage return, or control. If
either part of a hosted-branch description is unsafe, omit the whole synced
decoration. The renderer creates the ` / ` separator; it never accepts a remote template.

The state file uses the label-store threat model: safe absolute path,
non-symlinked owner-controlled parents, bounded regular data file, owner-only
permissions, strict parsing, duplicate-ambiguity rejection, and
same-directory atomic writes from an explicit helper only. Prompt rendering
does not create, repair, update, age, or delete it.

v0.2 initially has **no automatic refresh and no prompt-time expiry**. The
synced marker and verbose saved-at value make the point-in-time nature
reviewable. A future expiry policy needs its own product decision because it
would change when a safe decoration disappears; it may never refresh identity
or invoke the network from a prompt.

## Requirements for the future explicit sync flow

Issue [#6](https://github.com/junyoung2015/spaceship-supabase/issues/6) chooses
the exact helper command names and transport details, but it must follow this
proof chain:

1. Require a current safe root and valid live ref before remote work.
2. Run the Supabase CLI, credential lookup, and network operations only in an
   explicit user-invoked helper, outside prompt rendering.
3. For a top-level project, accept exactly one returned project whose ref
   equals the live ref. Never select by name, list position, or partial ref.
4. For a hosted branch, require or explicitly obtain a validated parent ref;
   validate the parent name and find exactly one branch whose branch-project
   ref equals the live ref. Do not silently scan an account or treat the
   linked branch ref as its parent.
5. Preview the exact proposed form, ref, source type, and storage action before
   persistence. Confirmation is required by default.
6. Re-resolve the live ref immediately before the atomic write. If it changed,
   became invalid, or no longer matches the proposal, write nothing.
7. On no match, multiple exact matches, auth failure, cancelled confirmation,
   unsupported output, unsafe text, interruption, or write failure, make no
   state change and use fixed/redacted diagnostics.
8. Never overwrite or silently convert a manual label. Offering a separate
   manual-label action requires a distinct confirmation and write path.

The helper API remains deliberately deferred to #6. A command name should not
become public API before its CLI-output variants, confirmation behavior, and
cross-version tests are designed.

## Failure behavior

| Condition | Required result |
| --- | --- |
| Invalid, missing, unreadable, oversized, multi-line, or symlinked live ref | Use a valid selected config mapping only if one exists; otherwise render nothing. Never recover it from state. |
| Invalid selected config mapping and no live ref | Render nothing. |
| Live ref changes in the same directory | Re-read it next prompt; decoration for the old ref no longer matches and is omitted. |
| Invalid, insecure, symlinked, oversized, duplicate-ambiguous, mismatched, or unsafe manual record | Omit only the label; retain independently valid identity/state. |
| Invalid, insecure, symlinked, oversized, duplicate-ambiguous, mismatched, or unsafe synced record | Omit only the synced decoration; retain live ref and any manual label. |
| Same-ref synced record contains an old remote name | Keep it only as a ref-bound synced snapshot; doctor shows saved-at time and it never claims freshness. |
| Matching manual label and synced record | Render the manual label; expose sync only through explicit verbose diagnostics/listing. |
| Configured mapping happens to match synced state | Never show synced text; retain `configured:<remote>`. |
| Unsafe optional local DB branch | Omit only `local-db:<name>`; retain independently valid live ref/decoration. |
| Unsupported format or disabled section | Render nothing and avoid unnecessary optional-state reads. |

No failure permits raw filesystem or remote bytes through the Spaceship v4
renderer. Normal prompt failures are silent; debug/helper diagnostics use fixed
codes and never echo raw records, labels, names, paths, credentials, or CLI
output.

## Issue handoff

- **#4 — this decision:** closes when this record is merged and linked from the
  roadmap.
- **#5 — local snapshot spike:** an undocumented telemetry file needs a
  distinct provenance decision; it is not a synced decoration by default.
- **#6 — explicit sync:** defines the helper API and implements the separate
  state record described here.
- **#7 — test gate:** proves identity, safety, state, Spaceship rendering,
  compatibility, freshness, and performance behavior.
- **#8 — public docs:** promotes only implemented behavior to user-facing
  reference docs while retaining this record as the provenance contract.

Until those issues land, v0.1.1 is unchanged: the default prompt shows only
the safe full ref, manual labels are the only human-readable decoration, and
the plugin neither reads nor writes remote-derived state.

## Decision checklist

- [x] Full validated ref remains visible in every human-readable form.
- [x] Project name, manual label, configured mapping, hosted branch, and local
  database branch have non-overlapping vocabulary.
- [x] Default display and remote-derived decoration reads are opt-in.
- [x] Manual labels have display precedence without replacing live identity.
- [x] Synced decorations have separate state, source, timestamp, and visible

  authorized by this decision alone.
